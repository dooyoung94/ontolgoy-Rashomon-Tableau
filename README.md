# 수집 데이터 기반 누락 토폴로지 관계 복원과 장애 원인 분석

## 연구 문제

운영 수집기는 서비스, 데이터베이스, 실행 위치, 추적, 지표, 로그를 수집할 수 있다. 그러나 기존 토폴로지에 객체 사이 관계가 없으면 수집된 객체를 하나의 구조로 연결하지 못한다.

본 연구의 질문은 다음과 같다.

> **수집 데이터는 존재하지만 기존 토폴로지에 관계가 없을 때, 수집된 실행 정보로 누락 관계를 복원할 수 있는가? 그리고 복원된 토폴로지가 실제 장애 원인 분석을 개선하는가?**

예:

```text
기존 토폴로지
frontend     orders     orders-pod     node-3

수집 데이터에는 실행 흔적이 있지만
토폴로지에는 관계가 없음

복원 결과
frontend  --호출--> orders
orders    --배포--> orders-pod
orders-pod --실행--> node-3
```

코드 내부 관계 이름은 `CALLS`, `DEPLOYED_ON`, `RUNS_ON`, `USES_DATABASE`, `USES_MESSAGING`, `HAS_SERVICE`를 사용한다.

---

## 전체 실험 흐름

```text
완전한 기준 토폴로지
        ↓
관계만 20% / 40% / 60% 제거
        ↓
불완전한 토폴로지

수집 데이터는 그대로 유지
        ↓
수집 단서에서 가능한 관계 생성
        ↓
문장 의미 검증
        ↓
규칙 기반 확률 검증
        ↓
누락 관계 복원
        ↓
복원 토폴로지
        ↓
OpenRCA 2.0 장애 원인 분석
```

### 실험에서 바꾸는 것

- 토폴로지 관계만 20%, 40%, 60% 제거한다.

### 실험에서 바꾸지 않는 것

- 수집 데이터는 삭제하지 않는다.
- 노드는 삭제하지 않는다.
- 제거한 관계가 무엇인지 모델에 알려주지 않는다.
- OpenRCA 2.0의 장애 원인 정답과 원인 경로는 평가에만 사용한다.

---

## 관계 복원 방법 비교

| 이름 | 구성 | 의미 |
|---|---|---|
| S0 | 복원 없음 | 관계가 빠진 토폴로지를 그대로 사용 |
| S1 | 귀추 | 수집 단서로 가능한 관계 생성 |
| S2 | 귀추 + DeBERTa | 문장 의미 검증 추가 |
| S3 | 귀추 + PSL | 규칙 기반 확률 검증 추가 |
| S4 | 귀추 + DeBERTa + PSL | 전체 방법 |

### 관계 복원 평가

남아 있는 관계 때문에 전체 점수가 높아지는 착시를 피하기 위해 **실제로 제거한 관계만 따로 평가**한다.

- 복원 정밀도
- 복원 재현율
- 복원 F1
- 관계 종류별 F1
- 복원 후 전체 토폴로지 F1은 보조 지표

---

## OpenRCA 2.0 장애 원인 분석 평가

관계 복원만 잘되었다고 연구가 끝나는 것이 아니다. 같은 장애에 대해 다음 세 조건을 비교한다.

```text
1. 관계가 빠진 토폴로지
2. 관계를 복원한 토폴로지
3. 완전한 기준 토폴로지
```

세 조건에서 **수집 데이터와 장애 데이터는 완전히 동일하고 토폴로지만 달라진다.**

평가값은 OpenRCA 2.0의 원인 및 원인 경로 평가에 맞춰 다음을 기록한다.

- 원인 서비스 하나 이상 적중
- 모든 원인 서비스 적중
- 원인 서비스 정밀도 / 재현율 / F1
- 원인 집합 완전 일치
- 1순위 원인 적중
- 3순위 안 원인 적중
- 원인에서 장애 현상까지 경로 도달
- 원인 과정 노드 F1
- 원인 과정 간선 F1

가장 중요한 비교는 다음이다.

```text
복원 토폴로지 점수 - 불완전 토폴로지 점수
```

특히 아래 네 값을 핵심으로 본다.

```text
원인 서비스 F1 변화
원인 경로 도달률 변화
노드 F1 변화
간선 F1 변화
```

기대 관계는 다음과 같다.

```text
불완전 토폴로지
        <
복원 토폴로지
        <=
완전 토폴로지
```

이 관계가 성립하지 않으면 단순히 토폴로지를 복원했다고 해서 장애 분석이 좋아진다고 주장할 수 없다.

---

## OpenRCA 2.0 사용 방식

OpenRCA 2.0은 500개 장애 사례와 단계별 원인 전파 정답을 제공한다. 본 연구에서는 이 정답을 **관계 복원 입력으로 사용하지 않고 장애 원인 분석 평가에만 사용**한다.

현재 토폴로지 실험은 통제 실험이다.

```text
수집 데이터에서 구성한 전체 구조
        ↓
일부 관계를 의도적으로 제거
        ↓
수집 데이터로 다시 복원
```

따라서 현재 결과는 **통제된 토폴로지 관계 누락 환경에서의 복원 및 장애 원인 분석 효과**로 표현한다.

## 코드 구조

```text
수집 데이터에서 관계 단서 생성
src/openrca_mr/structural.py

토폴로지 관계 제거 / 복원
src/openrca_mr/topology_recovery.py

관계 복원 평가
src/openrca_mr/stage1_eval.py

토폴로지 + OpenRCA 장애 원인 분석 통합 평가
src/openrca_mr/topology_rca_eval.py

관계 복원 실행
scripts/run_structural_recovery.py

통합 평가 실행
scripts/run_topology_rca_evaluation.py

자동 검증 및 실제 20건 실험
.github/workflows/openrca2-smoke.yml
```

### 관계 복원만 실행

```bash
python scripts/run_structural_recovery.py \
  --data artifacts/topology_cases.jsonl \
  --out results/s4_40.json \
  --variant abduction_deberta_psl \
  --topology-missing-ratio 0.40 \
  --seed 42
```

### 관계 복원 + 장애 원인 분석 실행

```bash
python scripts/run_topology_rca_evaluation.py \
  --data artifacts/topology_cases.jsonl \
  --out results/topology_rca_40.json \
  --topology-variant abduction_deberta_psl \
  --rca-variant full \
  --topology-missing-ratio 0.40 \
  --seed 42
```

## 현재 검증 단계

1. 단위검사
2. 실제 규칙 추론 검사
3. OpenRCA 2.0 실제 20개 사례에서 관계 누락 20%, 40%, 60% 검증
4. 20개 검증 후 전체 방법 비교
5. 최종 500개 사례 확장

이전의 수집 정보 삭제 실험, 인과 관계 라벨 삭제 실험, 정상/장애 구간 구조 일치도 실험은 현재 논문의 주 결과로 사용하지 않는다.
